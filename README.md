# Chat with your tables

A simple Python + Streamlit application for chatting with CSV and Excel data. Pandas reads uploads, DuckDB retrieves relevant evidence, and the OpenAI API generates SQL and explains query results. Code comments explain each step.

## Run on Windows (PowerShell)

Dependencies are already installed in the project `.venv`. Add your API key to `.env`:

```dotenv
OPENAI_API_KEY=your-api-key-here
```

Then run from this project directory:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Open the local URL printed by Streamlit, usually http://localhost:8501. Use Ctrl+C in the terminal to stop the app.

For a fresh installation (Python 3.10+):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# If .env is missing, create it from the example before adding your key.
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Do not overwrite an existing `.env` containing your key. On macOS/Linux, use `.venv/bin/python` instead of `.\.venv\Scripts\python.exe`.

## Try it

1. Upload `sample_data/sales.csv`, your own CSV, or an Excel workbook (`.xlsx` or `.xls`).
2. Expand the preview to inspect the table names and normalized column headers.
3. Ask “What is the total revenue by region?” (sample totals: North 2900, South 5100, East 2400).
4. Follow up with “Which region is highest?”
5. Expand “View SQL and supporting data” to inspect the evidence.

Multiple files are supported. Each nonempty workbook sheet becomes a separate table. Questions can join tables if matching keys exist; clarify the keys when their relationship is ambiguous. Changing the upload set clears the previous chat. “Clear chat” keeps the uploaded tables.

## How the RAG flow works

1. Pandas loads uploaded bytes into in-memory DataFrames.
2. OpenAI receives table schemas, a few sample rows, the question, and recent chat history. Structured outputs return a SQL query or a clarification.
3. The app validates the SQL and runs a single read-only query over uploaded tables in an isolated in-memory DuckDB database. External file/network access and extension loading are disabled during retrieval.
4. Retrieved rows become the context for a second OpenAI call, which generates the answer. SQL and evidence remain visible beside that answer.

This is **SQL-based table RAG**, with no embedding index or vector database. Exact filters, joins, aggregates, and text matching fit structured data well. Semantic similarity search across long free-text cells is not implemented. No Python generated by the model is executed.

## Configuration

Edit `.env` to change the model, upload limits, sample size, result limits, context size, history length, timeouts, or DuckDB resources. Changes are picked up on the next Streamlit interaction/rerun. Environment variables set outside the app take precedence over `.env`.

The default model is `gpt-4o-mini`; choose another Responses API model supporting structured outputs if desired. An OpenAI API account/key and available API billing/quota are required. `OPENAI_BASE_URL` is optional for a compatible provider; it must support the Responses API and structured outputs.

## Data and practical limits

- Uploads, previews, and chat are held in the current Streamlit session. Files are not intentionally saved to disk. Refreshing/restarting can clear the session; data is not persisted across app restarts.
- Table names, headers, sample values, questions, recent chat, and retrieved results are sent to your configured API provider. Both API calls use `store=False`. Provider retention policies still apply.
- CSVs must use UTF-8 encoding, with a header in the first row. Comma, semicolon, tab, and pipe delimiters are detected. Excel sheets need headers in the first row; encrypted workbooks are unsupported. Pandas reads saved formula values and does not calculate Excel formulas.
- Column names are converted to lowercase SQL identifiers; punctuation becomes underscores and collisions receive numbered suffixes. CSV date columns may be strings; queries can cast/parse them. Preview inferred data types if dates or numbers look wrong.
- DuckDB scans full tables for aggregate questions. Detailed results sent to the model are capped by `MAX_RESULT_ROWS` and `MAX_CONTEXT_CHARS`; the app labels truncation. Ask for an aggregate or a narrower filter if needed.
- Generated SQL uses a conservative function allowlist in `rag.py`. Unsupported functions, malformed queries, and resource-heavy queries can fail; rephrase the question or extend the allowlist with a safe analytical function.
- Upload limits reduce resource usage, but DuckDB's memory limit does not limit Pandas/Excel parsing. This is a simple local prototype. Public hosting needs authentication, stronger process isolation, and operational resource controls.
- Model answers may contain mistakes. Use the visible query and evidence to verify important conclusions.

## Files and checks

- `app.py`: upload, preview, and chat UI.
- `rag.py`: configuration, ingestion, SQL validation/retrieval, and OpenAI calls.
- `.env`: editable local settings and API key (ignored by Git).
- `.env.example`: safe configuration template.
- `requirements.txt`: dependency ranges.
- `requirements-lock.txt`: exact installed versions used for local verification.
- `tests/test_rag.py`: loading, SQL restrictions, retrieval, mocked API flow, and UI checks.

Run checks without an API key or network calls:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

API integration follows the [OpenAI structured outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs). SQL restrictions follow the [DuckDB security documentation](https://www.duckdb.org/docs/current/operations_manual/securing_duckdb/overview).
